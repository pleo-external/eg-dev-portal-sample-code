Pleo OAuth 2.0 – Visual Flow Dashboard

This dashboard is for illustration purposes only. It demonstrates the steps developers need to follow to get OAuth 2.0 working in Pleo's Staging environment so you can start testing APIs. It is bare-bones code and not intended for production use. For the full details visit: OAuth 2.0 Setup Workflow Guide and Integration Design details.

Step 1: Register OAuth Client
Client registration is assumed completed manually in Pleo’s Staging environment.
Client Secret must never be exposed to frontend code.
Redirect URIs are simplified here for localhost testing.
Distinguish public vs confidential clients.

Redirect URIs:

  • http://localhost:3000/connect
  • http://localhost:3000/oauth/callback

Step 5: Refresh Tokens

    

      Token refresh is triggered automatically when 30 seconds remain for demo purposes.

      In real integrations, refresh requests must be centralised to avoid race conditions.

      Refresh tokens are rotated: old tokens may expire after use.

      If refresh fails, the user must reauthenticate.

Step 6: Handle Token Expiry or Revocation

    

      Token revocation/expiry is not fully simulated here.

      In production, API calls must stop immediately when tokens are invalid.

      Logging and observability are critical.

      Reauthentication flow should be explicit and non-destructive.
